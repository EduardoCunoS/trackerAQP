\section{Modelo en VDM++}
\label{sec:modelo}

El componente crítico del sistema, el algoritmo de búsqueda de rutas, se
especificó como una clase VDM++ denominada \texttt{Sistema}. El modelo se
organiza en tipos, variables de instancia, funciones auxiliares y
operaciones con pre y postcondiciones, y cubre los elementos del lenguaje
requeridos: tipos \emph{quote}, \emph{token}, registros con invariantes,
secuencias, conjuntos y mapas. La Figura~\ref{fig:modelo} muestra el
modelo cargado en la VDM++ Toolbox.

\subsection{Tipos e invariantes}
\label{sec:tipos}

La especificación define un tipo \emph{quote} para el sentido del
recorrido, dos tipos \emph{token} para los identificadores opacos, y dos
tipos registro con sus invariantes:

\begin{lstlisting}
class Sistema
types
  public Sentido    = <IDA> | <VUELTA>;      -- quote
  public RutaId     = token;                 -- token
  public ParaderoId = token;                 -- token

  public Punto :: lat : real                 -- record
                  lng : real
  inv p == p.lat >= -90 and p.lat <= 90 and
           p.lng >= -180 and p.lng <= 180;

  public Recorrido :: ruta : RutaId          -- record
             sentido : Sentido
             coordenadas : seq of Punto
  inv r == len r.coordenadas >= 2;

instance variables
  recorridos : set of Recorrido := {};
  paraderos  : set of ParaderoId := {};
\end{lstlisting}

Los tipos \emph{quote} representan valores simbólicos de un dominio
cerrado (ida o vuelta). Los tipos \emph{token} representan identificadores
opacos que solo admiten igualdad, por lo que no es necesario conocer su
estructura interna. Los registros agrupan campos con nombre y sus
invariantes restringen los valores válidos: las coordenadas deben estar en
el rango geográfico ($-90^{\circ} \le lat \le 90^{\circ}$ y
$-180^{\circ} \le lng \le 180^{\circ}$) y todo recorrido debe tener al
menos dos puntos, pues un trayecto requiere origen y destino.

\subsection{Colecciones: secuencia, conjunto y mapa}
\label{sec:colecciones}

El modelo usa tanto secuencias como conjuntos. Las \textbf{secuencias}
(\texttt{seq of Punto}) se emplean para las coordenadas, porque el orden
de los puntos define el trayecto y un punto puede repetirse en una parada.
Los \textbf{conjuntos} (\texttt{set of Recorrido}, \texttt{set of
ParaderoId}) se emplean para los catálogos, donde el orden no importa y no
debe haber duplicados. Adicionalmente, se propone un \textbf{mapa} para
relacionar cada ruta con sus recorridos:

\begin{lstlisting}
recorridosPorRuta : map RutaId to set of Recorrido
inv recorridosPorRuta ==
  (forall r in set dom recorridosPorRuta &
     card recorridosPorRuta(r) <= 2)
  and
  (forall r in set dom recorridosPorRuta &
     forall rec in set recorridosPorRuta(r) & rec.ruta = r);
\end{lstlisting}

La invariante del mapa expresa que cada ruta tiene a lo sumo dos
recorridos (ida y vuelta) y que cada recorrido del mapa referencia a la
ruta que lo contiene.

\subsection{Implementación validada}
\label{sec:implementacion}

Por limitaciones de la versión de la Toolbox empleada (VDMTools 9.0.7),
la implementación ejecutable representa los tipos registro como tipos
producto y los identificadores \emph{token} como naturales, preservando la
semántica y las invariantes del modelo:

\begin{lstlisting}
types
  public Sentido   = <IDA> | <VUELTA>;
  public RutaId    = nat;
  public Punto     = real * real
    inv p == p.#1 >= -90 and p.#1 <= 90 and
             p.#2 >= -180 and p.#2 <= 180;
  public Recorrido = RutaId * Sentido * seq of Punto
    inv r == len r.#3 >= 2;
\end{lstlisting}

\subsection{Operaciones y postcondiciones}
\label{sec:operaciones}

Sobre la variable de instancia \texttt{recorridos : set of Recorrido} se
definen las operaciones de búsqueda. \texttt{buscarRutasDirectas} (RF1)
devuelve los recorridos que pasan a una distancia menor o igual a
\texttt{radio} del origen \texttt{A} y del destino \texttt{B} (en la
implementación con tuplas, el campo \texttt{coordenadas} se accede como
\texttt{rec.\#3}):

\begin{lstlisting}
public buscarRutasDirectas : Punto * Punto * real ==> set of Recorrido
buscarRutasDirectas(A, B, radio) ==
  return { rec | rec in set recorridos &
       cercaniaPunto(A, rec.#3) <= radio and
       cercaniaPunto(B, rec.#3) <= radio }
pre A <> B
post forall rec in set RESULT &
       cercaniaPunto(A, rec.#3) <= radio and
       cercaniaPunto(B, rec.#3) <= radio;
\end{lstlisting}

La postcondición formaliza la propiedad central: toda ruta devuelta se
encuentra a una distancia menor o igual al radio respecto del origen y
del destino. La operación \texttt{buscarRutasCombinadas} (RF2) extiende
la búsqueda a pares de recorridos conectados por un transbordo; su
postcondición exige además que las rutas sean distintas y que exista un
punto de transbordo dentro de \texttt{radioTransbordo}.
